## 一、项目概述

### 1.1 项目背景

面向非标作业场景（以菲达环保EPC工程总承包为落地场景），构建智衡云 · 非标作业智能成本管控体系。核心解决非标构件工时估算偏差大、成本异常发现滞后、成本数据不可溯源、多系统数据孤岛等问题。

系统覆盖**事前预测—事中监控—事后反馈**全闭环，包含6个角色工作台（工艺定额/车间管控/财务分析/采购外协/内审追溯/项目现场）和1个技术中心。

### 1.2 核心技术方案

- **工程图AI识别**：YOLOv8微调（构件目标检测）+ PaddleOCR（标题栏文字识别）+ OpenCV（图片预处理/版面分析）+ ODA File Drawings SDK（DWG解析）
- **AI工时估算**：多元线性回归模型，输入构件参数（重量/材质/复杂度/工序数/批量），输出预估工时+95%置信区间+置信度+SHAP归因
- **8项成本拆解**：钢材/人工/外协/设备/涂装/管理/安装，自动核算
- **5维异常检测**：规则引擎，实时检测工时偏差、钢材超耗、焊材浪费、外协超标、余废料异常
- **风险预警闭环**：预警触发→风险台账→责任分派→处置反馈→闭环验证
- **大模型根因分析**：LLM生成异常原因自然语言解释，人工确认后生效
- **数据飞轮**：实际成本数据自动回流训练集，模型持续迭代优化

### 1.3 技术栈

| 层级 | 技术选型 |
|---|---|
| 前端 | 原生HTML/CSS/JS，ECharts图表 |
| 后端 | 建议 Python FastAPI（AI推理服务）+ Node.js（业务API） |
| 数据库 | MySQL 8.0（业务数据）+ Redis（缓存/在线特征） |
| 对象存储 | MinIO / 阿里云OSS（工程图文件） |
| AI模型 | YOLOv8（构件检测）+ PaddleOCR（文字识别）+ scikit-learn 多元线性回归（工时估算） |
| 大模型 | Doubao / GPT-4o-mini，通过API网关调用 |
| 任务队列 | Celery + Redis（工程图识别异步任务） |
| 部署 | Docker + Docker Compose / K8s |

### 3.2 工时成本测算接口（P0）

**接口地址**：`POST /api/v1/work-orders/{id}/calculate`

**功能说明**：接收非标构件参数，调用多元线性回归模型计算预估工时，并基于物料价格和费率自动核算8项成本，返回SHAP归因和置信区间。

**请求头**：
```
Content-Type: application/json
Authorization: Bearer {token}
```

**请求体**（不传则用工单已有参数，传则覆盖）：
```json
{
  "weight": 1250.5,
  "material_coef": 1.15,
  "complexity": 3,
  "process_count": 6,
  "batch_size": 4,
  "steel_price": 4200
}
```

**请求字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| weight | decimal | **是** | 构件重量(kg) |
| material_coef | decimal | **是** | 材质系数：Q235=1.0/Q355=1.15/304=1.4/316L=1.6 |
| complexity | int | **是** | 结构复杂度1-5 |
| process_count | int | **是** | 工序数量3-12 |
| batch_size | int | **是** | 批量≥1 |
| steel_price | decimal | 否 | 钢材单价(元/吨)，默认4200 |

**成功响应**（200 OK）：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "est_hours": 42.8,
    "ci_low": 36.2,
    "ci_high": 49.4,
    "confidence": 0.82,
    "route_strategy": "人工复核",
    "cost_breakdown": {
      "steel": 5252,
      "labor": 4280,
      "outsource": 3852,
      "equip": 600,
      "coating": 1000,
      "manage": 1198,
      "install": 1500,
      "total": 17682
    },
    "shap_attribution": [
      {"feature": "板厚+焊缝", "value": 12.5, "unit": "h"},
      {"feature": "立焊位置", "value": 8.2, "unit": "h"},
      {"feature": "Q345R材质", "value": 5.8, "unit": "h"},
      {"feature": "批量效应", "value": -3.2, "unit": "h"}
    ],
    "inference_ms": 156
  }
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| est_hours | decimal | 预估工时(h) |
| ci_low | decimal | 95%置信区间下限 |
| ci_high | decimal | 95%置信区间上限 |
| confidence | decimal | 置信度0-1 |
| route_strategy | string | 路由策略：自动下达(≥0.9)/人工复核(0.7-0.9)/工程师接管(<0.7) |
| cost_breakdown | object | 8项成本拆解(元) |
| shap_attribution | array | SHAP归因，各特征对工时的贡献 |
| inference_ms | int | 推理耗时(ms) |

**模型公式（后端实现参考）**：
```
预估工时 = β₀ + β₁×重量 + β₂×材质系数 + β₃×复杂度 + β₄×工序数 + β₅×(1/批量) + β₆×历史均值

β₀=1.5, β₁=0.032, β₃=2.5, β₄=1.8, β₅=8.5, β₆=0.3
残差σ=2.8h，95%置信区间 = 预估 ± 1.96×σ
```

### 3.3 完工报工与异常检测接口（P0）

**接口地址**：`POST /api/v1/work-orders/{id}/complete`

**功能说明**：车间完工报工，系统自动对比预估值与实际值，进行5维异常检测，生成风险预警，工单流转至财务端。

**请求体**：
```json
{
  "actual_hours": 58.5,
  "actual_steel": 1320.5,
  "actual_weld": 22.3,
  "actual_outsource": 4500.00,
  "scrap_rate": 9.8,
  "remark": "因立焊位置操作难度大，工时超预期"
}
```

**检测维度与阈值**：

| 维度 | 预警阈值 | 异常阈值 | 说明 |
|---|---|---|---|
| 工时偏差 | >15% | >30% | 实际工时vs预估工时 |
| 钢材超耗 | >5% | >10% | 实际钢材消耗vs定额 |
| 焊材浪费 | >20% | >30% | 实际焊材消耗vs理论用量 |
| 外协超标 | >10% | >20% | 外协费用vs预算 |
| 余废料率 | >8% | >12% | 余废料重量vs总用料 |

### 3.5 工单状态流转接口（P0）

**接口地址**：`POST /api/v1/work-orders/{id}/{action}`

**action枚举**：

| action | 说明 | 触发角色 | 状态变化 |
|---|---|---|---|
| calculate | AI测算 | 工艺端 | pending_calc → pending_review |
| dispatch | 确认下达 | 工艺端 | pending_review → dispatched |
| start | 确认开工 | 车间端 | dispatched → in_production |
| complete | 完工报工 | 车间端 | in_production → completed（自动异常检测） |
| post | 财务过账 | 财务端 | completed → posted |
| audit | 内审审核 | 内审端 | posted → done |

**工单状态机**：
```
待测算(pending_calc) → 待复核(pending_review) → 已下达(dispatched)
    → 生产中(in_production) → 已完工(completed) → 已过账(posted)
    → 有异常→内审审核 / 无异常→已完成(done)
```

### 3.6 LLM根因分析接口（P1）

**接口地址**：`POST /api/v1/llm/rootcause`

**功能说明**：异常事件触发时，调用大模型生成自然语言根因分析和改进建议。输出必须经过校验，人工确认后才能进入业务流程。

**请求体**：
```json

  "anomaly_event_id": "AE-20260913-0001",
  "component_info": {
    "drawing_no": "FD-2026-0892",
    "material": "Q355",
    "weight": 1250.5,
    "complexity": 3
  },
  "anomaly_details": {
    "dimension": "hours",
    "predicted": 42.8,
    "actual": 58.5,
    "deviation": 36.7
  },
  "historical_context": {
    "similar_components_avg_deviation": 8.2,
    "team_new_hire_ratio": 0.4,
    "recent_rework_count": 2
  }
}
```

**成功响应**：
```json
{
  "code": 0,
  "data": {
    "analysis_id": "LLM-20260913-0001",
    "anomaly_event_id": "AE-20260913-0001",
    "root_cause": "该构件实际工时较AI预估高出36.7%，主要原因分析：1) 结构复杂度实际为4级（预估时按3级录入），导致焊接和拼装工时增加约8小时；2) Q355材质厚板焊接需预热，单道焊接时间增加约30%；3) 该班组近期新员工占比40%，熟练程度低于历史均值。建议：复核复杂度评级，调整Q355厚板焊接定额系数，关注该班组技能培训。",
    "confidence": 0.78,
    "requires_human_confirmation": true,
    "human_confirmed": false,
    "disclaimer": "本分析由AI生成，仅供参考，需人工确认后方可作为决策依据",
    "llm_model": "doubao-pro-32k"
  }
}
```

**大模型提示词边界（后端实现参考）**：

System Prompt 核心约束：
1. 只负责分析和解释，不做最终决策
2. 输出必须基于提供的数据，禁止编造数据
3. 数据不足时明确说明"数据不足，无法判断"
4. 禁止涉及责任认定和人员处罚建议
5. 每次输出末尾必须添加免责声明
6. 引用数据必须标注来源字段

### 4.2 work_orders 工单表（P0）

```sql
CREATE TABLE work_orders (
    id              VARCHAR(32) PRIMARY KEY COMMENT '工单号，如WO-20260901001',
    project         VARCHAR(128) NOT NULL COMMENT '所属项目',
    component       VARCHAR(64)  NOT NULL COMMENT '构件名称',
    material        VARCHAR(32)  NOT NULL COMMENT '材质',
    material_coef   DECIMAL(4,2) DEFAULT 1.0 COMMENT '材质系数',
    weight          DECIMAL(10,2) COMMENT '重量(kg)',
    thickness       INT          COMMENT '板厚(mm)',
    weld_length     DECIMAL(8,2) COMMENT '焊缝长度(m)',
    holes           INT          COMMENT '孔数',
    complexity      TINYINT      COMMENT '复杂度(1-5)',
    process_count   TINYINT      COMMENT '工序数',
    batch           INT          COMMENT '批量(件)',

    est_hours       DECIMAL(8,1) COMMENT '预估工时(h)',
    est_cost        DECIMAL(12,2) COMMENT '预估成本(元)',
    confidence      DECIMAL(3,2) COMMENT '置信度(0-1)',
    ci_low          DECIMAL(8,1) COMMENT '95%置信区间下限',
    ci_high         DECIMAL(8,1) COMMENT '95%置信区间上限',

    actual_hours    DECIMAL(8,1) COMMENT '实际工时(h)',
    actual_steel    DECIMAL(10,2) COMMENT '实际钢材消耗(kg)',
    actual_weld     DECIMAL(8,2) COMMENT '实际焊材消耗(kg)',
    actual_outsource DECIMAL(12,2) COMMENT '实际外协费用(元)',
    scrap_rate      DECIMAL(5,2) COMMENT '余废料率(%)',

    status          VARCHAR(32)  NOT NULL DEFAULT 'pending_calc' COMMENT '状态',
    stage           VARCHAR(32)  NOT NULL DEFAULT 'craft' COMMENT '当前阶段',
    current_handler VARCHAR(64)  COMMENT '当前处理人',

    drawing_id      VARCHAR(64)  COMMENT '关联工程图ID',
```

## 五、数据流转说明

### 5.1 主数据流

```
工程图上传 → AI识别 → 参数提取 → 创建工单 → AI工时成本测算
                                                    ↓
ERP系统 ──(钢材价格/定额/库存)──→ 特征工程 ──→ 回归模型
                                                    ↓
工单系统 ──(实际工时/工序进度)──→ 完工报工 → 5维异常检测
              ↓                                        ↓
         异常事件 ──→ LLM根因分析 ──→ 人工确认 ──→ 处置闭环
              ↓
         财务系统 ──(成本入账/凭证)──→ 成本归集 → 内审追溯
              ↓
         实际数据回流 → 训练集更新 → 模型迭代优化（数据飞轮）
```

### 5.2 6角色业务流转

```
工艺定额端：待办队列 → AI测算 → 置信度路由 → 确认下达
     ↓
车间管控端：接收工单 → 确认开工 → 完工报工（自动异常检测）
     ↓
财务分析端：预归集复核 → 过账 → 异常推送内审
     ↓
内审追溯端：异常工单审核 → 全链路追溯 → 风险台账闭环
     ↓
完成（数据回流训练集）
```

### 5.3 数据同步频率

| 数据类型 | 来源 | 同步方式 | 频率 |
|---|---|---|---|
| 钢材价格 | ERP | REST API | 每日 |
| 工时定额 | ERP | REST API + CSV备份 | 每月 |
| BOM物料清单 | PDM | API | 实时 |
| 实际工时 | 工单系统 | 消息队列/API | 实时 |
| 物资出入库 | WMS | API | 实时 |
| 财务凭证 | 财务系统 | API | 日结 |

### 5.4 数据清洗规则

| 规则 | 触发条件 | 处理方式 |
|---|---|---|
| 重量缺失 | weight为null或0 | 按图纸估算，标记imputed=true |
| 工时异常高 | actual_hours > 1000 | 标记异常，不进入训练集 |
| 3σ离群点 | \|x-μ\| > 3σ | 剔除训练集，保留原始库 |
| 单位不统一 | 重量单位为吨/克 | 自动转换为kg |
| 重复记录 | wo_id+timestamp重复 | 去重，保留最新 |

## 八、注意事项

1. **模型系数可配置**：回归模型的β系数不要写死，放在model_registry表中，支持版本管理和动态更新
2. **特征快照必须存**：每次预测的输入特征要以JSON形式存入，保证可溯源
3. **LLM输出必须人工确认**：所有大模型生成的内容默认"待确认"状态，不能直接进入业务流程
4. **置信度路由**：≥0.9自动下达，0.7-0.9人工复核，<0.7工程师接管
5. **5维异常检测阈值**：工时>15%/30%、钢材>5%/10%、焊材>20%/30%、外协>10%/20%、余废料>8%/12%
6. **风险闭环机制**：预警→台账→分派→处置→验证→闭环，全流程留痕
7. **数据脱敏**：供应商名称、客户项目信息等敏感字段，训练和展示时需要脱敏
8. **审计日志**：所有关键操作（定额下达、异常确认、成本过账、风险闭环）必须留痕，保留5年
9. **工程图识别异步**：识别耗时10-30秒，必须用异步任务，前端轮询结果
10. **数据飞轮**：实际成本数据确认后自动回流训练集，定期触发模型重训
