# 智衡云 — 面向非标作业场景的智能作业成本管控系统

## ——系统介绍与功能说明

---

## 一、项目背景

### 1.1 行业痛点

在环保设备EPC工程总承包、重型装备制造等非标作业场景下，成本管控长期面临"三难"困境：

| 痛点 | 具体表现 |
|------|---------|
| **成本难预测** | 非标构件无标准定额，工时估算依赖老师傅经验，误差率常超20% |
| **过程难跟踪** | 生产过程数据分散在ERP、工单、财务等多个系统，成本异常发现滞后 |
| **结果难闭环** | 项目结束后成本数据未回流，模型无法持续优化，同类错误反复发生 |

### 1.2 命题背景

本项目基于菲达环保（环保设备EPC工程总承包企业）的真实业务场景，两大钢结构智造基地（诸暨牌头、江苏盐城）年产值超10亿元，非标构件占比超70%。

行业数据显示：年产值1000万-5亿元的非标企业中，**逾60%存在成本核算失真问题**，项目平均利润率从2021年的7.2%降至2024年的4.1%。

---

## 二、系统目标

构建一个**"事前预测—事中监控—事后反馈"**全闭环的非标作业智能成本管控系统，实现：

1. **精确性**：工时估算误差率从20%+降至12%以内
2. **实时性**：成本异常从"事后发现"变为"事中预警"，响应时间从天级缩短至小时级
3. **闭环性**：实际成本数据自动回流训练集，模型持续迭代优化
4. **可解释性**：AI预测结果可溯源、可解释，满足内审与内控要求

## 三、核心功能（四大功能模块）

### 3.1 功能一：工程图AI识别研判（事前·核心）

**功能描述**：基于大量历史数据训练，对环保EPC项目制作工艺图作AI识别和研判，自动分析测度用料数量、成本以及所需制作工时。

**技术实现**：
- **图纸解析层**：ODA File Drawings SDK解析DWG，OpenCV预处理，PaddleOCR识别标题栏
- **AI识别层**：YOLOv8微调识别构件族（焊架/箱体/法兰/异形等），几何计算+规则引擎自动测算重量/焊缝长度
- **成本预测层**：多元线性回归模型估算工时+8项成本拆解+市场价格联动

**识别输出**：
- 构件类型、数量、位置
- 重量、材质、板厚、焊缝长度、孔数
- 复杂度评级（1-5）、工序数
- 预估工时（含95%置信区间）
- 8项成本拆解（钢材/人工/外协/设备/涂装/管理/安装）

---

### 3.2 功能二：成本拆解动态预测（事前）

**功能描述**：基于大量历史数据训练，并结合业态的市场化变动/宏观经济环境，对不同规格的产品进行成本拆解、分析、预测。

**AI工时估算模型（多元线性回归）**：

```
预估工时 = β₀ + β₁×重量 + β₂×材质系数 + β₃×复杂度 + β₄×工序数 + β₅×(1/批量) + β₆×历史均值

β₀=1.5, β₁=0.032, β₃=2.5, β₄=1.8, β₅=8.5, β₆=0.3
残差σ=2.8h，95%CI = 预估 ± 1.96σ
```

**特征说明**：
| 特征 | 取值范围 | 说明 |
|------|---------|------|
| 重量 | 50-5000kg | 构件净重，工程图自动测算 |
| 材质系数 | 1.0-1.6 | Q235=1.0/Q355=1.15/304=1.4/316L=1.6 |
| 复杂度 | 1-5 | 图元密度+工序数自动评级 |
| 工序数 | 3-12 | 切割/卷板/焊接/钻孔/涂装等 |
| 批量效应 | 1/批量 | 批量越大单件工时越低 |
| 历史均值 | — | 相似构件历史平均工时修正 |

**模型性能**：R²=0.84，MAPE=11.8%

**置信度路由机制**：
- **≥0.9**：自动下达定额
- **0.7-0.9**：人工复核
- **<0.7**：工程师接管

---

### 3.3 功能三：全维度风险预警闭环（事中）

**功能描述**：实时监控钢材、配件等余废料、账外物资的变动情况，对成本、费用状况进行一站式跟踪，结合前期预算及进度预期进行进度和风险预警。

**5维异常检测体系**：

| 检测维度 | 预警阈值 | 异常阈值 | 说明 |
|---------|---------|---------|------|
| 工时偏差 | >15% | >30% | 实际工时vs预估工时 |
| 钢材超耗 | >5% | >10% | 实际钢材消耗vs定额 |
| 焊材浪费 | >20% | >30% | 实际焊材消耗vs理论用量 |
| 外协超标 | >10% | >20% | 外协费用vs预算 |
| 余废料率 | >8% | >12% | 余废料重量vs总用料 |

**全链条风险识别**（覆盖命题要求的4类风险）：
- 流程风险：工序跳步、审批缺失、进度滞后
- 数据风险：数据缺失、异常值、单位不统一
- 财税合规风险：成本归集错误、发票异常、税务风险
- 人员与组织影响风险：岗位变革、技能要求变化、组织调整

**风险闭环处置机制**：
1. **预警触发**：超阈值自动生成风险预警
2. **风险台账**：所有预警进入风险台账，分级管理
3. **责任分派**：按风险类型自动分派至对应部门
4. **处置反馈**：责任人填写处置措施与结果
5. **闭环验证**：内审验证处置效果，关闭风险项

---

### 3.4 功能四：评价体系与反馈闭环（事后）

**功能描述**：一是对成本管控的精确性进行测算、反馈，数据进入训练集，优化AI识别研判的精准度；二是通过建设AI成本管控效果可量化的评价指标体系，对成本管控精确性、数据优化程度等进行定期评估。

**可量化评价指标体系**：

| 指标类别 | 具体指标 | 计算方式 |
|---------|---------|---------|
| **精确性指标** | 工时估算MAPE | \|实际-预估\|/实际 × 100% |
| | 成本估算误差率 | \|实际成本-预估成本\|/预估成本 |
| | 置信度准确率 | 高置信工单实际达标率 |
| **效率指标** | 定额编制周期 | 从工程图到定额下达的时间 |
| | 异常响应时间 | 从异常发生到处置的时间 |
| | 结账周期 | 从完工到成本归集完成的时间 |
| **效益指标** | 成本降低率 | (基线成本-实际成本)/基线成本 |
| | 余废料降低率 | 余废料率同比变化 |
| | 返工率降低 | 返工工时占比同比变化 |
| **数据质量指标** | 数据完整率 | 完整字段数/总字段数 |
| | 数据准确率 | 抽检正确数/抽检总数 |
| | 数据及时率 | 按时上报数/应上报总数 |

**数据飞轮闭环**：
```
工程图识别 → 成本预测 → 生产执行 → 实际数据采集 → 误差分析
    ↑                                                          ↓
    └────────── 模型迭代优化 ←── 数据入训练集 ←─────────────┘
```

## 五、业务流程（6角色端到端流转）

### 5.1 六大角色工作台

| 角色 | 核心职责 | 关键功能 |
|------|---------|---------|
| **工艺定额端** | 工时定额测算与下达 | 工程图识别→AI测算→置信度路由→定额下达 |
| **车间管控端** | 生产过程管控与报工 | 接收工单→开工确认→完工报工→余废料台账 |
| **财务分析端** | 成本归集与差异分析 | 预归集复核→过账→月度差异分析→大额会签 |
| **采购外协端** | 采购外协成本管控 | 采购申请审批→AI智能比价→外协订单跟踪 |
| **内审追溯端** | 异常审核与全链路追溯 | 异常工单审核→风险台账→全链路追溯→审计报表 |
| **项目现场端** | 现场成本数据采集 | 现场上报→巡检记录→材料签收→影像资料 |

### 5.2 端到端业务流转

```
技术出图 → 工程图AI识别 → BOM拆解 → 作业定额下达
     ↓
物料计划审批 → 物资领用 → 工序加工 → 产品质检 → 成品入库
     ↓
非标件交付 → 财务成本归集 → 异常检测 → 内审追溯
     ↓
实际数据回流 → 模型迭代优化（数据飞轮）
```

### 5.3 工单状态机

```
待测算(pending_calc)
    ↓ 测算
待复核(pending_review)
    ↓ 确认下达
已下达(dispatched) → 车间管控端
    ↓ 确认开工
生产中(in_production)
    ↓ 完工报工（5维异常检测）
已完工(completed) → 财务分析端
    ↓ 过账
已过账(posted) → 有异常→内审追溯端 / 无异常→完成
    ↓ 内审通过
已完成(done)
```

## 六、创新点

### 6.1 技术创新

1. **工程图AI识别+成本预测一体化**：将计算机视觉（YOLOv8+OCR）与回归模型结合，实现从工程图到成本定额的全自动转化，替代传统人工识图+经验估算模式

2. **小样本迁移学习优化**：针对非标构件样本少的痛点，采用迁移学习，基于相似构件族预训练模型微调，新构件类型仅需少量样本即可达到可用精度

3. **置信度路由机制**：根据AI预测置信度自动分流（≥0.9自动下达/0.7-0.9人工复核/<0.7工程师接管），在效率与准确性之间取得平衡

4. **SHAP可解释性归因**：每个AI预测结果都附带SHAP归因分析，明确各特征对预测结果的贡献度，满足内审可追溯要求

### 6.2 业务创新

1. **事前-事中-事后全闭环**：突破传统成本管控"事后核算"模式，实现事前精准预测、事中实时预警、事后反馈优化的全生命周期管控

2. **5维异常检测体系**：从工时、钢材、焊材、外协、余废料五个维度建立量化阈值，实现成本异常的自动识别与分级预警

3. **数据飞轮持续优化**：实际成本数据自动回流训练集，模型持续迭代，预测精度随使用时间不断提升

### 6.3 跨学科创新

- **计算机+会计跨学科融合**：将AI计算机视觉、机器学习技术与管理会计、成本会计理论深度结合，解决非标作业成本管控这一跨学科难题
- **技术人员+财务人员协同**：系统设计充分考虑两类用户的使用习惯与专业术语，实现技术语言与财务语言的自动转换

## 七、演示方式

### 7.1 系统启动

> **重要**：不要直接双击打开 index.html（file://协议），否则多个页面之间数据无法共享，端到端业务流程跑不通。必须用本地服务器方式打开，访问地址形如 `http://localhost:8000`。

#### 方式一：Windows 一键启动（推荐）

1. 双击项目文件夹里的 `启动服务器.bat`
2. 脚本会自动检测 Python、自动选择可用端口（8000被占用会自动改用8080/8888），并在2秒后自动打开浏览器
3. 若浏览器没有自动弹出，按黑窗口提示手动访问 `http://localhost:8000`
4. 演示结束后，**关闭黑色命令窗口**即停止服务器

脚本特性：三重Python检测（python / py / python3）、端口自动避让、出错时窗口不会闪退并提示原因。

#### 方式二：Mac / Linux 启动

1. 打开终端（Terminal）
2. 输入 `cd` 空格，将项目文件夹拖入终端，按回车
3. 首次使用输入 `chmod +x 启动服务器.sh` 添加执行权限
4. 输入 `./启动服务器.sh` 启动
5. 浏览器访问 `http://localhost:8000`

#### 方式三：命令行直接启动（全平台通用）

1. 终端（Windows用命令提示符CMD或PowerShell）进入项目文件夹
2. 输入 `python3 -m http.server 8000`（Windows若提示找不到 python3，改用 `python -m http.server 8000`）
3. 浏览器访问 `http://localhost:8000`
4. 停止服务器在终端按 `Ctrl + C`

#### 常见问题排查

| 问题现象 | 原因 | 解决办法 |
|---|---|---|
| 双击bat后黑窗口一闪而过 | 旧版本脚本出错即退出；端口被占用或未装Python | 使用最新版bat（已修复，不会闪退，会显示具体原因） |
| 提示"未检测到Python" | 电脑没装Python，或安装时没勾选 Add to PATH | 到 https://www.python.org/downloads/ 下载安装，安装时务必勾选最下方 "Add Python to PATH" |
| 提示端口8000被占用 | 其他程序占用了8000端口 | 新版脚本会自动改用8080/8888，按窗口提示的地址访问即可 |
| 浏览器显示"无法访问此网站" | 服务器还没启动好就打开了页面 | 等2秒刷新页面（F5）即可 |
| 页面能打开但数据不联动/各角色页面数据不同步 | 用了 file:// 协议直接双击打开 | 必须用上面三种本地服务器方式之一打开 |

#### 兜底方案（无法安装Python时）

- **方案A：使用 Node.js**。安装 Node.js（https://nodejs.org/）后，在项目文件夹执行 `npx http-server -p 8000`，新版Windows脚本也会自动检测并调用。
- **方案B：使用 VS Code 的 Live Server 插件**。用VS Code打开项目文件夹，安装 "Live Server" 插件，在 index.html 上右键 → "Open with Live Server"。
