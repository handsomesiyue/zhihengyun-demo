技术实现方案

图纸解析层

  • DWG解析：ODA File Drawings SDK 提取几何实体与标注
  • PDF/图片：OpenCV 预处理 + 版面分析
  • 标题栏OCR：PaddleOCR 识别图号、名称、材质、比例
  • 图层分离：按线型/颜色区分轮廓线、标注线、中心线

AI识别层

  • 构件检测：YOLOv8 微调，识别焊架/箱体/法兰/异形等构件族
  • 参数提取：几何计算 + 规则引擎，自动测算重量/焊缝长度
  • 材质识别：标题栏OCR + 材料表关联，映射材质系数
  • 复杂度评级：图元密度 + 工序数 + 特征点，自动评级1-5

成本预测层（功能2）

  • 工时估算：多元线性回归模型，输入识别出的构件参数，输出预估工时+置信区间
  • 成本拆解：8项成本自动核算（钢材/焊材/人工/外协/设备/余料/管理/安装）
  • 市场联动：钢材价格实时对接ERP，外协单价参考历史中标价，宏观经济指标调整系数
  • 小样本优化：新构件类型采用迁移学习，基于相似构件族预训练模型微调
智能定额模型 — 先验引导的残差学习（Prior-Guided Residual GBDT）
为什么不是"一个大模型训练到底"。非标场景的困难不在算法，而在样本量与可解释性： 一家环保装备企业一年也只有几百条有效结算记录，端到端训练必然过拟合；而成本核算要能追责—— 财务不接受"模型说多少就是多少"。因此本系统把预测拆成两段：
① 先验（不可学习）：企业《2024工时标准》明文规定的结算单价，或同类部件历史中位数；
② 残差（可学习）：GBDT 只学 ln(实际 ÷ 先验)，即"先验说不清的那部分"。
输出的每一次预测都能拆成「标准是多少 → 我们调整了多少 → 为什么调整」，可直接进审计底稿。

① 两阶段模型形式

先验： P = 工时标准[x] 若命中；否则 = median(同类族)
目标： r = ln(y / P)  （对数残差，抑制长尾）
拟合： r̂ = GBDT0.5(x)   # pinball α=0.5 → 中位
区间： [ GBDT0.1(x), GBDT0.9(x) ] + 共形外扩 δ
输出： ŷ = P · exp( r̂ )
22 维特征：ln(吨位)、ln(先验)、跨月结算次数、分厂 one-hot、
是否海外 / 批量件 / 备件 / 包装发运、部件族 one-hot ×15。

② 为什么这样能压住小样本过拟合

  • 对数残差目标：单位成本跨两个数量级（20 ~ 1400 元/吨），直接回归会被极端值绑架；取对数后长尾被压缩，且天然是乘性模型，符合"吨位越大单位成本越低"的规模效应
  • 先验承载主效应：吨位、工艺这些大趋势由企业标准先扛住，GBDT 只需学小修正，有效容量需求大幅下降
  • 直方图分箱 + 叶子数/最小样本正则：自研 GBDT 用 255 箱直方图加速，max_leaves 与 min_samples_leaf 双重约束
  • 按项目分组交叉验证：同一项目的部件绝不跨训练/验证集，杜绝"同工程内部相关性"抬虚指标

③ 共形推断 CQR：给区间一个覆盖保证

分位数回归不保证真实覆盖率。本系统在交叉验证的折外预测上计算一致性分数， 取 δ = ⌈(n+1)(1−α)⌉ / n 分位数，把区间两侧等量外扩， 使区间在分布无关前提下达到名义覆盖率（无需假设正态/对数正态）。
关键细节：共形校正必须与模型在同一坐标系进行。本系统在对数空间校正（δ=0.047，两侧各外扩 4.8%）； 若在绝对值空间校正，δ 会被大吨位件拉到百万量级，区间直接失真。

④ 精确 TreeSHAP 归因（不是 Saabas 近似）

Shapley 值是唯一满足有效性、对称性、Dummy、可加性四条公理的归因方法。 本系统实现的是 Lundberg 的 TreeSHAP 多项式时间精确算法（沿树做子集枚举并记录覆盖权重）， 而非"按分裂增益分摊"的 Saabas 近似。自测中用蒙特卡洛穷举 Shapley 值交叉核验，最大偏差 1.2e-2（属采样噪声量级）。
因此前端展示的归因严格满足 基准值 + Σ各特征贡献 = 模型输出，可逐项加总验算。

⑤ 孤立森林 Isolation Forest（无监督异常检测）

非标场景下"异常"没有标签。用孤立森林在 4 个可解释量（ln 吨位、ln 单位成本、ln 先验、ln 实际/先验）上做无监督检测： 随机划分空间，异常点因更容易被孤立而路径更短。异常分 s = 2−E(h)/c(n)， 越接近 1 越异常。命中记录直接作为内审线索，落到内审工作台。

⑥ EWMA 控制图（统计过程控制 SPC）

钢材月度均价用 EWMA 监控：Zt = λ·xt + (1−λ)·Zt−1（λ=0.25）， 控制限 UCL/LCL = CL ± L·σ·√(λ/(2−λ))。相比普通 X̄ 图，EWMA 对小幅持续漂移的灵敏度显著更高—— 钢材涨价通常是缓慢爬升而非单月跳涨，这正是选它的原因。越限点自动生成采购核查线索。

⑦ 蒙特卡洛成本风险仿真（VaR / CVaR）

8 个成本项按各自分布抽样（钢材/工时取对数正态，其余取正态）， 三个波动源全部来自真实数据：钢材 σ 取自 2024 采购明细月度对数收益标准差（19.26%）、 工时 σ 由模型共形区间反解、余废料率取台账分布。
输出 P50 / P95、VaR95（95% 置信下最大损失）与 CVaR95（最坏 5% 情形的平均超额—— CVaR 是一致性风险度量，弥补 VaR 不满足次可加性的缺陷），并给出龙卷风敏感度排序， 直接告诉管理者"该盯哪一项"。

⑧ 挣值管理 EVM（EV ≠ AC）

很多"成本跟踪"令 EV ≡ AC，于是 CPI 恒等于 1，挣值管理退化成记账。本系统把三条线分开：
· PV：公司基准投放曲线按项目活跃窗口缩放
· EV：按工期计提，每个部件在真实活跃月份区间内均匀挣取预算
· AC：台账逐月累计结算额
由此得到有区分度的 CPI / SPI，并外推 EAC = AC + (BAC−EV)/CPI 与完工偏差 VAC。

⑨ 为什么全部用 NumPy 自研，而不是直接调 XGBoost / LightGBM

工程上当然可以直接 pip install xgboost。但我们选择自己实现 GBDT、TreeSHAP、孤立森林、蒙特卡洛， 理由是交付约束 + 答辩可解释：
· 比赛现场环境不确定，零第三方 ML 依赖意味着交付包在任何一台装了 Python 的机器上都能跑起来，不会因为编译环境、glibc 版本翻车；
· 算法逐行可控、可核验——评委问"你的 Shapley 值怎么算的""区间覆盖率怎么保证"，能直接翻到实现，而不是回答"库里带的"；
· 所有模块均有自测脚本（TreeSHAP 与蒙特卡洛穷举交叉核验、分位数覆盖率、EWMA 误报率、对数正态参数反解），共 7 项，全部通过。
核心算法集中在 backend/services/ml_core.py（约 900 行，纯 NumPy）。

你是一个专业的成本分析助手。

【角色定位】
只负责分析和解释异常原因，不做最终决策。

【输出约束】
1. 必须基于提供的数据，禁止编造数据
